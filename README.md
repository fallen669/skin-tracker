# skin-tracker

Трекер цен на скины CS2. Снимает котировки со **Skinport** и **Waxpeer**, считает
спреды с учётом комиссий, копит историю в SQLite и шлёт находки в Discord.

Цель — не торговать, а **за месяц собрать данные и понять, есть ли вообще маржа**.
Сделки жмёшь руками: автоматизация аккаунта Steam нарушает Subscriber Agreement,
и банят за это реально.

## Установка

Зависимостей нет — только Node.js 22.5+ (`fetch` и `node:sqlite` встроены).

```bash
cd C:\projects\skin-tracker
copy .env.example .env
```

Дальше открой `.env` и вставь вебхук Discord: канал → Настройки → Интеграции →
Вебхуки → Создать → Копировать URL. Без него всё работает, просто пишет в консоль.

## Запуск

```bash
npm run once
```

Один цикл — проверить, что всё живо.

```bash
npm start
```

Бесконечный цикл каждые 10 минут. Оставь работать на месяц.

```bash
npm run report
```

Сводка по накопленным данным. Это и есть ответ на исходный вопрос.

## Запуск в GitHub Actions (24/7 без сервера)

Workflow в `.github/workflows/track.yml` запускается по cron каждые 15 минут,
собирает котировки и коммитит их обратно в репозиторий.

1. Создай репозиторий и запушь проект (команды ниже).
2. Settings → Secrets and variables → Actions → **New repository secret**:
   имя `DISCORD_WEBHOOK`, значение — URL вебхука.
3. Settings → Actions → General → Workflow permissions → **Read and write
   permissions**. Без этого коммит данных упадёт.
4. Вкладка Actions → track → **Run workflow** — проверить руками.

### Почему данные лежат в NDJSON, а не в SQLite

Контейнер Actions умирает после каждого запуска, значит состояние должно жить
в репозитории. Коммитить SQLite-файл каждые 15 минут нельзя: git хранит бинарник
целиком на каждый коммит, за месяц это гигабайты. Append-only NDJSON, разбитый
по дням, сжимается дельтами и читается глазами.

SQLite остаётся форматом анализа — собирается локально:

```bash
git pull
npm run import
npm run report
```

### Что нужно знать про Actions

- **Cron не точный.** Задержки в 10–30 минут — норма, под нагрузкой запуск
  могут пропустить. Считай это «примерно 4 раза в час».
- **Расписание отключается**, если в репозитории 60 дней нет активности.
  Коммиты от самого workflow активностью не считаются — придётся раз в пару
  месяцев запускать вручную.
- **Лимит Skinport — не скользящее окно, а бан.** Превысил 8 запросов за 5 минут
  — получаешь `Retry-After: 3132`, то есть 52 минуты. При 2 запросах за прогон
  и cron раз в 15 минут выходит 8 запросов в час при лимите 96, запас большой.
  Но не гоняй `Run workflow` руками подряд.
- На публичном репозитории минуты Actions бесплатны и не ограничены.
  Данные при этом видны всем — если не хочешь, делай приватный (2000 мин/мес,
  этой задаче хватает с большим запасом).

## Что он на самом деле считает

Покупка по нижнему листингу на площадке A, перевыставление на B, минус комиссия B:

```
net = sellPrice × (1 − feeB) − buyPrice
```

**Обе цены — это цены выставления, а не сделок.** Значит любая цифра здесь —
верхняя граница. Реальность хуже: дешёвый листинг может быть протухшим или
дешёвым не просто так, а твоё перевыставление ещё должно продаться.

## Фильтры, и зачем каждый

Первые прогоны показывали «маржу» в 265% и 346%. Ни одна не была настоящей.
Каждый фильтр закрывает конкретный способ соврать:

| Фильтр | Что ловит |
|---|---|
| `MAX_LOCK_SKEW` | Трейд-лок. У Skinport `tradable=0` — это книга **без** лока: меньше листингов, выше пол. Waxpeer лок не помечает вообще. Сравнение разлоченного пола с залоченным давало те самые 265%. |
| `excludeNamePatterns` | Фазы и паттерны. У `Gamma Doppler Phase 1` и `Gamma Doppler Emerald` **один** `market_hash_name`. Дешёвый листинг — обычная фаза, дорогой — Emerald. Сравнивать бессмысленно. |
| `excludeCategoryPatterns` | Стикеры, капсулы, граффити: тонкие книги, другая динамика, `quantity` значит не то же самое. |
| `MIN_ANCHOR_RATIO` / `MAX_ANCHOR_RATIO` | Выбросы. Якорь — медиана Skinport. Цена сильно ниже неё это не находка, а другой вариант предмета или битый листинг. |
| `MIN_LISTINGS` | Ликвидность. На книге из трёх листингов один чудак задаёт «рыночную цену». |
| `MIN_NET_PROFIT_USD` | Мелочь. 55% от скина за $6 — это $3.40. |

Комиссии в `.env` — **проверь под свой аккаунт**. У Skinport она падает с оборотом,
и обе площадки меняли сетку не раз.

## Как читать отчёт

Главный блок — **«Живучесть»**.

Спред, который держится больше 5 циклов, почти наверняка ненастоящий. Если бы
можно было купить на A и продать на B, кто-нибудь уже закрыл бы разницу.
Живучий спред означает, что дешёвая сторона дешева по причине: плохой float,
залоченный предмет, отсутствующие стикеры, скам-листинг.

Настоящие возможности выглядят как **разовые срабатывания** — появились и исчезли.
Если через месяц в колонке «разовые» пусто, а всё висит в «>5 циклов» — ответ на
вопрос «есть ли смысл в торговом боте» получен, и он отрицательный.

## Steam

Выключен по умолчанию (`STEAM_ENABLED=false`). Два повода:

1. Нет батч-эндпоинта — один HTTP-запрос на предмет, и 429 начинается примерно
   после 20 запросов в минуту.
2. **Деньги из кошелька Steam не выводятся.** Спред против Steam — не кэш.
   Полезен только как проверка вменяемости цены на стороннем рынке.

Поэтому в расчёте Steam никогда не выступает стороной продажи.

## Ограничения

- Считает по цене нижнего листинга, а не по фактическим сделкам.
- Не знает float, стикеры, паттерн, нейм-теги — а они определяют цену.
- Не учитывает трейд-холды: 7 дней без мобильного аутентификатора, 15 если
  добавил его недавно. Капитал заморожен, цена уезжает.
- Комиссии зашиты константами, а не читаются из API.
- Данные площадок кэшированы: Skinport 5 минут, Waxpeer — как повезёт.

## Структура

```
.github/workflows/
  track.yml      cron каждые 15 мин, коммитит данные в репозиторий
src/
  index.js       цикл: собрать → сохранить → посчитать → уведомить
  config.js      всё через .env
  db.js          SQLite, пишет только изменившиеся цены
  storage.js     append-only NDJSON для CI
  import.js      NDJSON → SQLite для локального анализа
  analyze.js     фильтры и расчёт спреда
  notify.js      Discord webhook
  report.js      сводка по накопленному
  sources/
    skinport.js  две книги: со всеми листингами и без залоченных
    waxpeer.js   цены в 1/1000 USD
    steam.js     по одному предмету, с backoff на 429
```

Режим хранения переключается переменной `STORAGE`: по умолчанию `sqlite`
(долгоживущий локальный процесс), в CI — `ndjson`.
